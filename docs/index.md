# 项目文档

面向人类与 Agent 的文档入口。改代码前先读相关文档；行为 / 意图 / 架构变更须同步更新。

## 文档根路径

若因老项目冲突改用了非默认路径，以本表为准（后续会话先读此表）。

| 角色 | 路径 |
|------|------|
| 产品意图 | `docs/intent/` |
| 行为规格 | `docs/spec/` |
| 架构决策 | `docs/adr/` |
| 调研记录 | `docs/research/` |

## 写什么、何时写

| 目录 | 写什么 | 何时写 |
|------|--------|--------|
| intent | 为什么做、给谁、成功标准、约束、明确不做 | 产品意图或范围变化；新功能意图确认后 |
| spec | 用户可感知行为、规则、验收要点 | 行为变化；实现前把约定写清 |
| adr | 架构/技术取舍、备选方案、后果 | 做出或变更重要技术决策时 |
| research | 调研结论、官方资料清单、候选方案对比（非决策） | 重要调研完成时；决策落地后再转 adr/spec |

纯样式 / 文案 / 重构且行为不变 → 可不写文档；若已有 spec 写到相关细节则顺手改。

## 工作流摘要

1. 意图不清 → 先澄清（如 interview-me）→ 落 intent → 必要时写 spec → 再改代码
2. 禁止先写代码再补文档
3. ADR 只增不删；变更时新开编号并标记 supersede
